Looking at `TelecomCallActionReceiver.kt:57-77`:
```kotlin
when (action) {
```

## 4. One-Way Audio: Strongest Root Cause

**Telecom (system) and LiveKit (FlutterWebRTC) own separate audio sessions. Telecom sets `MODE_IN_COMMUNICATION` and controls routing (earpiece/speaker) via `AudioManager`. LiveKit/FlutterWebRTC independently creates an `AudioTrack` with `USAGE_VOICE_COMMUNICATION`. When Telecom acquires audio focus and routes to earpiece, LiveKit's AudioTrack may be silenced (`silenced:true`) because it's not the focus owner. The non-deterministic `silenced:true/false` across sessions is a race: whichever audio session gets focus last wins.**

**File + Function + Line:**  
`mobile/android/app/src/main/kotlin/com/example/mobile/CallConnectionService.kt:221` — `connection.setAudioModeIsVoip(true)` activates Telecom audio mode WITHOUT requesting audio focus for the LiveKit session.  
`mobile/lib/services/livekit_call.dart:88-114` — `_enableAndVerifyMicrophone()` publishes local audio but never coordinates with Telecom's audio focus/routing.

## 11. LIVEKIT ANALYSIS

### CLAIM
**LiveKit is configured in default `automatic` audio management mode, which conflicts with Telecom. Correct mode for Telecom-integrated apps is `externalCallSystem`.**

### SOURCE EVIDENCE
1. `livekit_call.dart:21-26` — `Room()` created with `RoomOptions(adaptiveStream: false, dynacast: false)` — NO audio session options
2. `livekit_call.dart:13-58` — `connect()` calls `_room!.connect()` then `_enableAndVerifyMicrophone()` — No prior `LiveKitClient.initialize()`
3. `livekit_call.dart:63-66` — `setSpeaker()` no-op: "Telecom owns routing" — Acknowledges Telecom ownership but doesn't configure LiveKit accordingly

### OFFICIAL LIVEKIT 2.11.0 DOCS
- `AudioSessionManagementMode.externalCallSystem` — "The application uses an external call system (like CallKit or Telecom) to manage the audio session. LiveKit will not activate/deactivate the audio session, request audio focus, or set the audio mode."
- Required initialization:
  ```dart
  LiveKitClient.initialize(
    initialAudioSessionOptions: AudioSessionOptions.communication(),
  );
  LiveKitClient.setAudioSessionManagementMode(AudioSessionManagementMode.externalCallSystem);
  ```

### CONFIDENCE: 95%
### VERDICT: **PROVEN** — LiveKit in wrong mode for Telecom integration
